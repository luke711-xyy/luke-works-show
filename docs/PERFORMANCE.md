# 移动端性能优化 · 2026-10-20

本轮保留既有宣纸、水墨荷叶、锦鲤、中文器物模型与真实 Bayer 抖色，不用静态图标替换动态场景。

## 定位与处理

- 手机地址栏伸缩导致 `resize` 时，旧实现会释放并重建整池几何、材质和模型。现在同宽的竖屏高度变化只重排对象并调整相机，保留资源与动画对象。
- 首屏不再同步构造八个复杂项目徽记；视角接近后每帧至多准备一个附近模型，创建时立即绑定对象深度带与长卷接缝裁切。
- 640px 以下使用 1× 绘制缓冲、30fps 动画预算；叶面从 7,488 减至 3,456 个三角形，保持相同轮廓、褶皱函数、宽幅积墨和受光配色。桌面保留完整几何与 1.5× 上限。
- WebGL 模块从入口拆出，语义 DOM 先显示。入口业务 JS 从约 102.3kB 降至 42.9kB；Three.js 与模型代码仍需要按模块下载，并非消失。
- 案例导航状态提交后立即暂停场景绘制，不再与对话框展开、截图解码竞争；历史状态写入失败不阻塞界面。触摸轻点在 `pointerup` 提交；距离阈值及原生横滑取消保留，兼容 click 去重；鼠标与键盘保持可用。
- 修复首帧 RAF 时间戳稍早于场景初始化时的负动画时间，防止编钟索引越界。
- 手机默认使用从原图生成的 720px 原彩 WebP（quality 92），23 张合计约 1.2MB；三级图片不再做 Bayer 量化。桌面清晰大图、原图查看和视频按需播放保留；一、二级程序场景继续真实抖色。
- 入卷、长卷当前项、指针意图及按下时预热封面；低优先级预热串行执行，离开即取消后续队列。详情只主动预热下一张，后续由原生 lazy loading 跟随滚动；省流量/2G 不做后台预热。内存最多保留 12 张预热图。
- `public/_headers` 对哈希 JS/CSS 与哈希手机版图片使用一年 immutable，对可变图片/字体/宣纸使用短缓存与重验证。不缓存整站 HTML，不引入可能固化旧应用的全站离线 Service Worker。

## 验证边界

本地桌面 Chromium 的 390×700/720 iframe，同一检查夹具测得：高度变动停顿约 299 → 20ms；原生鼠标点击至 dialog 打开约 49 → 27ms；独立触摸事件路径约 21ms。它们是本机样本，不是真机或公网慢网性能保证；iframe RAF 间隔也不是 GPU 渲染帧率。

回归覆盖：手机高度变化不释放几何、首页不构造离屏徽记、按需徽记的深度带、绘制缓冲预算、案例打开立即暂停/关闭恢复、首帧负时钟、低优先级请求升级、预热串行与取消、移动图片路由及内容哈希。另校验 24 个原始素材哈希、23 张清晰图像素一致性、48 个既有媒体 URL。

重新生成手机版资源：`npm run assets:responsive`；完整素材准备 `npm run assets` 也会同步生成。新文件在 `public/media-mobile/`，内容哈希用于更新失效，版本信息在 `src/data/media-responsive.generated.json`。

缓存头已随 2026-10-21 的鱼鳍细化版本发布，发布证据见 `docs/DEPLOYMENT.md`；后续导航及题字更新仍需各自完成发布验收。实际手机、移动网络及重复访问条件下的性能仍需实机复测，不以桌面尺寸模拟代替。
