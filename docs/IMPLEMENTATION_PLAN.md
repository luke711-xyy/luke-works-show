# 代码实现方案与验收计划

## 已锁定的交付

静态中文作品集，React + TypeScript + Vite + Three.js。在当前目录建立工程，保留原始 Word、截图和视频。先绘制实际运行的纸纹／荷叶／花／鱼样片，再逐步扩展八个项目。概念图用于校准视觉，不作为整页背景替代交互场景。

## 架构

| 子系统 | 职责 | 边界 |
| --- | --- | --- |
| `src/data` | 八个项目的叙述、媒体顺序、源码／体验入口、鱼与图形标识 | 不保存运行时动画状态 |
| `src/scene` | 场景生命周期、程序化几何、抖色通道、叶片弹簧、鱼的运动 | 常驻一个主 renderer；React 切页不销毁它 |
| `src/components` | 画布桥接、原图查看、视频与详情阅读 | 语义化 DOM 与焦点管理 |
| `src/App.tsx` | 路由、页面状态、横向容器与场景同步 | 帧更新通过 ref／scene API，避免 React 每帧 render |
| `scripts/prepare-media.mjs` | 仅读取源素材，输出抖色／清晰衍生图、纸纹、视频、媒体清单 | 所有输出限定在 public 与生成数据目录；运行前后校验源文件散列 |

ProjectRecord 持有 id、标题、短介绍、概况段落、关键选择、媒体 ID、源码链接、可选体验链接和 emblem 类别。媒体清单持有清晰与抖色 URL、尺寸、来源文件名与校验信息。

## 路由与恢复

- `/`：荷塘。
- `/works?focus=<id>`：横向长卷；站内从锦鲤进入时沿相邻长卷快速滑到目标，首次直接访问或刷新则直接恢复目标位置。
- `/works/<id>`：直接访问项目详情。
- history state 记录长卷位置；popstate、关闭详情与返回荷塘恢复同一条鱼和所在位置。
- 首次直接访问作品详情时，不强制播放首页过场。

## 渲染

1. 正交相机，以斜俯角观察世界 XZ 水平面。几何拥有真实高度、交叠与深度。
2. 纸纹作为独立 CSS 平面，主画布背景透明。
3. 场景先渲染到离屏目标，再执行固定 CSS 像素网格、Bayer 8×8 阈值与有限色阶量化。
4. 可见世界包含荷叶、花、锦鲤和项目图形；抖色前进行运动与灯光计算，网格不会随着模型抖动。
5. 荷叶是有缺口、卷边和径向叶脉的曲面；鱼有真实轮廓、眼、鳍与尾部摆动。避免圆形卡片或图标替代整个场景。
6. DPR 和离屏目标有上限。持续压力下调整动画节奏及环境数量，不随机改变已确定的材质粒度。

## 运动与命中

### 荷塘
- 八条鱼分配互不拥挤的 home 区域，运行时 seed 控制随机航点与停留时长，调试 seed 可复现。
- 鱼以受限加速度与转角朝航点行进；边界约束与成对避让共同生效。
- 指针投影到水面，以椭圆距离计算叶片推力；阻尼弹簧驱动偏移和回弹。
- 点击时检查叶片当前轮廓与鱼的实际命中顺序。可见抖色小孔不提供隔叶点击。
- hover 鱼只轻微放大与显名，不吸附指针、不换鱼、不停止游动。

### 转场与长卷
- 状态：`pond → entering → guiding → returning`，长卷只有连续水道巡游，不切换整圈绕叶模式。
- `Journey.x` 为自动过场的位置权威：荷塘在世界 x=0，长卷最左端始终在 x=viewport width。相机以一条 smoothstep 曲线向目标移动，不在接缝重启缓动；返回先回长卷起点，再穿过接缝回荷塘。
- 长卷 `scrollLeft=max(0, cameraX-width)`，两侧 DOM 的相邻边界和场景共用同一坐标。程序同步产生的 scroll 事件不反向改写目标；正常浏览仍由原生 scrollLeft 驱动场景。外层 overflow: clip 防止聚焦造成父级水平滚动。
- 两侧植物与阴影在固定接缝裁切，不因跨界覆盖后按进度隐藏而突变。选中锦鲤不受该边界裁切，自动滑动时随相机平移，普通滚动时保留轻微领先／落后；水纹使用连续相机位移，不在交接结束时重置滚动偏移。
- 领游目标在上下水道间缓慢变化，沿附近叶缘让开；惯性跟随与缓变转向保持连贯。快速／反向滚动只影响领先、落后和随行，不触发闭合绕圈。
- 详情覆盖场景时暂停不可见高耗更新，关闭后恢复时间连续性。

## 输入与详情

- 长卷原生 overflow-x；纵向wheel按原方向映射到X（正deltaY向右），保留像素／行／页单位换算、触控板细粒度与主轴判断。三级详情恢复浏览器原生纵向滚动，不挂载wheel拦截器；原生横向wheel、键盘、手机直接触摸和Ctrl／缩放不拦截。
- 手机在首页拖动拨叶，点击已露出的鱼进入；长卷原生横滑；详情原生纵向滚动。
- 项目详情采用原生 dialog，进入时从选中荷叶轮廓展开；ESC、关闭和浏览器后退均工作。
- 截图默认抖色，独立查看器支持清晰原图和放大。视频使用离线 Bayer 处理后的 MP4，按需加载并保留播放控制。
- 场景中的项目提供对应语义按钮；键盘聚焦时让叶片显露目标。减少动态模式保留可用入口。

## 实施顺序

1. 工程与素材管线、内容与路由纯函数。
2. 单组荷叶／花／鱼视觉样片，校准真实 shader 与纸纹。
3. 完整一级荷塘、巡游、避让、拨叶与命中。
4. 单项目连续切屏、URL 和返回恢复。
5. 八项目长卷、原生滚动、领游及绕叶。
6. 八份有各自重点的详情、原图和视频。
7. 手机、键盘、减少动态、无 WebGL、性能与生产构建。
8. 实际浏览器截图和交互检查，集中修正，再完成交付记录。

## 验证

纯逻辑测试：路由解析、导航恢复、随机巡游边界、避让、坐标换算、转场端点、叶间巡游高度与边界、滚动转向连续性、Bayer 阈值范围。

浏览器检查：1440×900、1920×1080、390×844 与平板。实际拨叶和点鱼、切屏到目标、正反横滑、详情纵向阅读、原图切换、视频播放、关闭／后退、键盘路径与减少动态。连续进出后检查 renderer 数量及控制台。

质量门槛：轮廓可识别、层次与留白成立、像素网格稳定、鱼不互穿、操作不误触，正文与截图能读。性能结论按浏览器实际测量报告，目标为普通桌面接近 60fps、移动端稳定 30fps。

## 证据约束

MOSIC 的现代 dither 参考固定为公开 `codex/music-cockpit-ui` 分支的 renderer 与 shaders。Worldmaker 的切片／导出和 MCP 明确标注对应分支与进展。Water Reminder 不使用未核实的精度、时延、成本或无限缓存承诺。个人职责与业务成果不由代码作者列表推断。
